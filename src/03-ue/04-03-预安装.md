# InstallPrerequisites.bat 逐行解析

> 源文件路径：`G:\CarlaUE5\Util\SetupUtils\InstallPrerequisites.bat`  
> 调用者：`CarlaSetup.bat`（第 59 行 `call Util/SetupUtils/InstallPrerequisites.bat --python-path=%python_path%`）

---

## 一、脚本概述

这是 CARLA UE5 在 Windows 上的前提依赖安装脚本，负责检查并安装三样东西：

1. **Visual Studio 2022**（含指定组件）
2. **Ninja 构建系统**（v1.12.1）
3. **Python**（默认 3.8.10）+ pip 包

脚本会逐个检查每项是否已存在，存在就跳过，不存在就自动下载安装。

---

## 二、命令行参数

| 参数                 | 作用                         |
| -------------------- | ---------------------------- |
| `--python-path=PATH` | 指定要使用的 Python 命令路径 |
| `--python-path PATH` | 同上，空格分隔               |
| `-pypath PATH`       | 同上，简写                   |

不传则默认用 `python`（系统 PATH 中的）。

## 三、逐段解析

### 3.1 头部与版本号定义（第 1-8 行）

```bat
@echo off
setlocal EnableDelayedExpansion
```

- `@echo off` — 关闭命令回显
- `setlocal EnableDelayedExpansion` — 开启延迟变量扩展，后续用 `!var!` 取实时值

```bat
set ninja_version=1.12.1
set python_path=python
set python_version_default=3.8.10
```

定义三个常量：

- `ninja_version` — 要安装的 Ninja 版本号，用于下载 URL 拼接
- `python_path` — 默认 Python 命令，后续可被参数覆盖
- `python_version_default` — 如果需要自动安装 Python，用这个版本

### 3.2 Visual Studio 组件列表（第 9-21 行）

```bat
set visual_studio_components=^
    Microsoft.VisualStudio.Workload.NativeDesktop ^
    Microsoft.VisualStudio.Workload.NativeGame ^
    Microsoft.VisualStudio.Workload.ManagedDesktop ^
    Microsoft.VisualStudio.Component.Windows10SDK.22621 ^
    Microsoft.VisualStudio.Component.VC.CMake.Project ^
    Microsoft.Net.Component.4.8.SDK ^

    Microsoft.VisualStudio.Component.VC.Llvm.Clang ^
    Microsoft.VisualStudio.Component.VC.Llvm.ClangToolset ^
    Microsoft.VisualStudio.ComponentGroup.NativeDesktop.Llvm.Clang ^
    Microsoft.VisualStudio.Component.VC.14.36.17.6.x86.x64 ^
    Microsoft.Component.PythonTools
```

`^` 是续行符，把这些组件 ID 拼成一个字符串。每个组件的含义：

| 组件 ID                                                      | 含义                                                         |
| ------------------------------------------------------------ | ------------------------------------------------------------ |
| `Microsoft.VisualStudio.Workload.NativeDesktop`              | C++ 桌面开发工作负载（含 MSVC 编译器、ATL、MFC）             |
| `Microsoft.VisualStudio.Workload.NativeGame`                 | C++ 游戏开发工作负载（含 UE5 所需的调试工具）                |
| `Microsoft.VisualStudio.Workload.ManagedDesktop`             | .NET 桌面开发工作负载                                        |
| `Microsoft.VisualStudio.Component.Windows10SDK.22621`        | Windows 10 SDK 10.0.22621（编译 CARLA 需要的 SDK 版本）      |
| `Microsoft.VisualStudio.Component.VC.CMake.Project`          | VS 内置的 CMake 工具                                         |
| `Microsoft.Net.Component.4.8.SDK`                            | .NET Framework 4.8 SDK                                       |
| `Microsoft.Net.ComponentGroup.4.8.1.DeveloperTools`          | .NET 4.8.1 开发工具                                          |
| `Microsoft.VisualStudio.Component.VC.Llvm.Clang`             | LLVM/Clang 编译器                                            |
| `Microsoft.VisualStudio.Component.VC.Llvm.ClangToolset`      | Clang 工具集（用于 MSBuild 的 Clang 集成）                   |
| `Microsoft.VisualStudio.ComponentGroup.NativeDesktop.Llvm.Clang` | 桌面 C++ 的 Clang 组件组                                     |
| `Microsoft.VisualStudio.Component.VC.14.36.17.6.x86.x64`     | MSVC v14.36 工具集（VS 2022 17.6 版本的 C++ 编译器，CARLA 指定版本） |
| `Microsoft.Component.PythonTools`                            | Python 开发工具                                              |

> **为什么需要 Clang？** CARLA 部分代码用 Clang 编译，部分用 MSVC 编译。Clang 工具集是与 MSVC 共存的。

> **为什么锁定 MSVC v14.36？** CARLA 团队在测试时使用的是 VS 2022 17.6 版本对应的编译器。更新的 MSVC 版本（如 17.10+ 对应的 v14.40）可能导致 googletest 等第三方库编译失败。

### 3.3 命令行参数解析（第 23-45 行）

```bat
:parse
    if "%1"=="" (
        goto main
    )
    echo %1 | findstr /B /C:"--python-path=" >nul
    if not errorlevel 1 (
        set python_path="%1"
        set python_path="!python_path:--python-path=!"
    ) else if "%1"=="--python-path" (
        set python_path=%2
        shift
    ) else if "%1"=="-pypath" (
        set python_path=%2
        shift
    ) else (
        echo Unknown argument "%1"
        exit /b
    )
    shift
    goto parse
```

解析逻辑和 `CarlaSetup.bat` 中的参数解析一样：

1. `%1` 为空 → 跳转到 `:main`
2. 检查 `--python-path=PATH` 形式 — 用 `findstr` 检测前缀，字符串替换提取路径
3. 检查 `--python-path PATH` 形式 — 取下一个参数 `%2`，然后 `shift` 跳过
4. 检查 `-pypath PATH` 简写 — 同上
5. 未知参数 → 报错退出
6. `shift` + `goto parse` 循环

### 3.4 检查并安装 Visual Studio 2022（第 50-78 行）

```bat
:main

setlocal EnableDelayedExpansion
set "vs_found=false"
if exist "%PROGRAMFILES%\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat" (
    set "vs_found=true"
)
if exist "%PROGRAMFILES%\Microsoft Visual Studio\2022\Professional\VC\Auxiliary\Build\vcvars64.bat" (
    set "vs_found=true"
)
if exist "%PROGRAMFILES%\Microsoft Visual Studio\2022\Enterprise\VC\Auxiliary\Build\vcvars64.bat" (
    set "vs_found=true"
)
```

依次检查 Community、Professional、Enterprise 三个版本。检查的标志文件是 `vcvars64.bat`（VS 的 C++ 开发环境激活脚本）。只要任意一个存在，`vs_found` 设为 `true`。

> **注意：** 这里只检查 VS 是否安装，不检查是否安装了前面列的那些组件。如果你装了 VS 但没勾选游戏开发工作负载，脚本不会发现。

```bat
if "!vs_found!"=="true" (
    echo Found Visual Studio 2022.
    goto end_vs_install
) else (
    echo Could not find Visual Studio 2022. Downloading...
)
```

找到就跳到 `:end_vs_install`，不安装。

```bat
if not exist %cd%\Temp (
    mkdir %cd%\Temp
)
pushd Temp
curl -L -O https://aka.ms/vs/17/release/vs_community.exe || exit /b
popd Temp
```

找不到 VS 时：

- 创建临时目录 `Temp`
- `curl -L -O` 下载 VS 2022 Community 安装器
  - `-L` 跟随重定向
  - `-O` 用 URL 中的文件名保存（即 `vs_community.exe`）
  - `https://aka.ms/vs/17/release/vs_community.exe` 是微软官方短链接

```bat
%cd%\Temp\vs_community.exe --add %visual_studio_components% --installWhileDownloading --passive --wait || exit /b
del %cd%\Temp\vs_community.exe
rmdir %cd%\Temp
```

- `%cd%\Temp\vs_community.exe` — 运行安装器
- `--add %visual_studio_components%` — 安装前面定义的所有组件
- `--installWhileDownloading` — 边下载边安装，节省时间
- `--passive` — 静默安装（有进度条但不需要用户点击）
- `--wait` — 等待安装完成后才继续
- `|| exit /b` — 安装失败则脚本终止
- `del` + `rmdir` — 清理安装器和临时目录

```bat
:end_vs_install
```

标签，跳过安装时直接到这里。

### 3.5 检查并安装 Ninja（第 82-94 行）

```bat
ninja --version >nul 2>nul
if errorlevel 1 (
    echo Could not find Ninja. Downloading...
    curl -L -o %USERPROFILE%\AppData\Local\Microsoft\WindowsApps\ninja-win.zip https://github.com/ninja-build/ninja/releases/download/v%ninja_version%/ninja-win.zip || exit /b
    powershell -command "Expand-Archive $env:USERPROFILE\AppData\Local\Microsoft\WindowsApps\ninja-win.zip $env:USERPROFILE\AppData\Local\Microsoft\WindowsApps\ninja-win" || exit /b
    move %USERPROFILE%\AppData\Local\Microsoft\WindowsApps\ninja-win\ninja.exe %USERPROFILE%\AppData\Local\Microsoft\WindowsApps\ninja.exe || exit /b
    rmdir /s /q %USERPROFILE%\AppData\Local\Microsoft\WindowsApps\ninja-win
    del /f %USERPROFILE%\AppData\Local\Microsoft\WindowsApps\ninja-win.zip
    echo Installed Ninja %ninja_version%.
) else (
    echo Found Ninja.
)
```

逐行拆解：

1. `ninja --version >nul 2>nul` — 尝试运行 `ninja --version`，标准输出和错误都丢弃
2. `if errorlevel 1` — 如果返回非零（ninja 不存在或不可执行）
3. `curl -L -o ... ninja-win.zip` — 从 GitHub 下载 Ninja 压缩包
   - 下载 URL：`https://github.com/ninja-build/ninja/releases/download/v1.12.1/ninja-win.zip`
   - 保存到：`%USERPROFILE%\AppData\Local\Microsoft\WindowsApps\`（这个目录已在 PATH 中）
4. `powershell -command "Expand-Archive ..."` — 用 PowerShell 解压 zip
5. `move ... ninja.exe` — 把解压出来的 `ninja.exe` 移到 WindowsApps 根目录
6. `rmdir /s /q` — 删掉解压产生的临时文件夹（`/s` 递归删除子目录，`/q` 不确认）
7. `del /f` — 删掉 zip 文件（`/f` 强制删除只读文件）
8. `echo Found Ninja.` — 如果 ninja 已存在，直接跳过

> **为什么放到 WindowsApps？** 这个目录默认在系统 PATH 中，放进去后 `ninja` 命令全局可用。

### 3.6 检查并安装 Python（第 96-108 行）

```bat
%python_path% -V >nul 2>nul
if errorlevel 1 (
    echo Could not find Python. Downloading...
    echo Installing Python %python_version_default%...
    curl -L -O https://www.python.org/ftp/python/%python_version_default%/python-%python_version_default%-amd64.exe || exit /b
    python-%python_version_default%-amd64.exe /passive PrependPath=1 || exit /b
    del python-%python_version_default%-amd64.exe
    set "PATH=%LocalAppData%\Programs\Python\Python38\Scripts\;%LocalAppData%\Programs\Python\Python38\;%PATH%"
    echo Installed Python %python_version_default%.
) else (
    echo Found Python.
)
```

逐行拆解：

1. `%python_path% -V >nul 2>nul` — 尝试运行 `python -V` 查看版本
   - `%python_path%` 是变量，可能是 `python`（默认）或 `--python-path` 指定的路径
2. `if errorlevel 1` — 如果 Python 不存在
3. `curl -L -O https://www.python.org/ftp/python/3.8.10/python-3.8.10-amd64.exe` — 从 python.org 下载安装器
   - `-O` 用 URL 中的文件名保存
4. `python-3.8.10-amd64.exe /passive PrependPath=1` — 运行安装器
   - `/passive` — 静默安装（显示进度条但不需用户操作）
   - `PrependPath=1` — 自动将 Python 添加到系统 PATH
5. `del python-...exe` — 删除安装器
6. `set "PATH=...\Python38\Scripts\;...\Python38\;%PATH%"` — 把 Python 3.8 的 Scripts 和主目录加入当前 shell 的 PATH
   - 即使安装器的 `PrependPath` 生效了，当前 shell 也需要手动添加（因为 setx 只影响新开的 shell）
7. `echo Found Python.` — 如果 Python 已存在，直接跳过

> **注意：** 默认下载的是 Python 3.8.10。但 CARLA UE5 官方文档说也支持 3.9 和 3.10。如果想用已有的 Python 环境（如 conda），通过 `--python-root` 参数指定即可跳过此步。

### 3.7 安装 Python 包（第 110-112 行）

```bat
%python_path% -m pip install --upgrade pip || exit /b
%python_path% -m pip install -r requirements.txt || exit /b
```

1. `pip install --upgrade pip` — 先升级 pip 自身
2. `pip install -r requirements.txt` — 安装 `requirements.txt` 中列出的包

**requirements.txt 内容：**

| 包名                 | 作用                                                         |
| -------------------- | ------------------------------------------------------------ |
| `psutil`             | 系统信息库（进程、CPU、内存等），CARLA Python API 用它监控模拟器状态 |
| `requests`           | HTTP 库，用于下载资产文件                                    |
| `scikit-build-core`  | Python 的 CMake 构建集成工具，用于编译 Python 扩展模块       |
| `wheel`              | Python wheel 包格式支持，安装 .whl 文件需要                  |
| `numpy<2.0,>=1.24.4` | 数值计算库，版本限制在 1.24.4~2.0 之间（CARLA 不兼容 numpy 2.0） |
| `setuptools>=47.3.1` | Python 打包工具，构建 carla 包需要                           |
| `build`              | PEP 517 构建前端，用于构建 Python 包                         |
| `pygame`             | 游戏开发库，CARLA 的手动控制示例脚本用它来显示窗口           |

## 四、脚本完整执行流程图

```
InstallPrerequisites.bat
│
├─ 解析命令行参数 (--python-path)
│
├─ 检查 Visual Studio 2022
│   ├─ 找到 vcvars64.bat → 跳过

│   ├─ python -V 成功 → 跳过

│
└─ 安装 Python 包
    ├─ pip install --upgrade pip
    └─ pip install -r requirements.txt
        (psutil, requests, scikit-build-core, wheel,
         numpy<2.0, setuptools, build, pygame)
```
