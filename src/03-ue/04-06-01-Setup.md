## 一、Setup.bat（实际内容）

> 路径：`G:\UnrealEngineCarla\Setup.bat`

```bat
@echo off
setlocal
pushd "%~dp0"
```

- `@echo off` — 关闭命令回显
- `setlocal` — 创建局部变量作用域
- `pushd "%~dp0"` — 切换到脚本所在目录（引擎根目录 `G:\UnrealEngineCarla`），保存原目录到栈

```bat
rem Figure out if we should append the -prompt argument
set PROMPT_ARGUMENT=
for %%P in (%*) do if /I "%%P" == "--prompt" goto no_prompt_argument
for %%P in (%*) do if /I "%%P" == "--force" goto no_prompt_argument
set PROMPT_ARGUMENT=--prompt
:no_prompt_argument
```

- 遍历所有命令行参数 `%*`，逐个赋值给 `%%P`
- 如果用户已传了 `--prompt` 或 `--force`，不重复添加
- 否则设 `PROMPT_ARGUMENT=--prompt` — 让 GitDependencies 在下载每个文件前询问用户确认
- **如果你想要无人值守运行，传 `--force` 参数跳过确认**

```bat
rem Sync the dependencies...
.\Engine\Binaries\DotNET\GitDependencies\win-x64\GitDependencies.exe %PROMPT_ARGUMENT% %*
if %ERRORLEVEL% NEQ 0 goto error
```

- **核心步骤** — 运行 `GitDependencies.exe`
- 路径：`Engine\Binaries\DotNET\GitDependencies\win-x64\GitDependencies.exe`
- 这个 .NET 程序读取 `.gitdeps` 文件（如果存在），从 Epic 的 CDN 下载二进制依赖
- 传入 `--prompt`（或用户的参数 `%*`）
- `%ERRORLEVEL% NEQ 0` — 如果返回非零（失败或用户取消），跳到 `:error`
- **这步会下载约 10-20GB 的二进制文件**

```bat
rem Setup the git hooks...
if not exist .git\hooks goto no_git_hooks_directory
echo Registering git hooks...
echo #!/bin/sh >.git\hooks\post-checkout
echo Engine/Binaries/DotNET/GitDependencies/win-x64/GitDependencies.exe %* >>.git\hooks\post-checkout
echo #!/bin/sh >.git\hooks\post-merge
echo Engine/Binaries/DotNET/GitDependencies/win-x64/GitDependencies.exe %* >>.git\hooks\post-merge
:no_git_hooks_directory
```

- 安装两个 git hooks：
  - `post-checkout` — 每次 `git checkout` 切换分支后自动运行 GitDependencies 同步依赖
  - `post-merge` — 每次 `git pull` / `git merge` 后自动同步依赖
- hook 内容就是调用 GitDependencies.exe 并传入原始参数
- 这样切换分支或拉取更新后，二进制依赖会自动保持正确版本
- 如果 `.git\hooks` 目录不存在则跳过

```bat
rem Install prerequisites...
echo Installing prerequisites...
start /wait Engine\Extras\Redist\en-us\UEPrereqSetup_x64.exe /quiet /norestart
```

- 安装 UE5 运行时系统前提（VC++ Redistributable、DirectX Runtime 等）
- `start /wait` — 启动程序并等待其完成
- `/quiet` — 静默安装，无 UI
- `/norestart` — 不自动重启
- **此 exe 需要 Setup.bat 第一步下载后才会存在**

```bat
rem Register the engine installation...
if not exist .\Engine\Binaries\Win64\UnrealVersionSelector-Win64-Shipping.exe goto :no_unreal_version_selector
.\Engine\Binaries\Win64\UnrealVersionSelector-Win64-Shipping.exe /register
:no_unreal_version_selector
```

- 注册 UE5 安装到 Windows 注册表
- `UnrealVersionSelector` — Epic 的引擎注册工具
- `/register` — 写入注册表项，让 Epic Games Launcher 能发现此引擎
- 让 .uproject 文件关联到此引擎版本
- 如果该 exe 不存在则跳过

```bat
rem Done!
goto :end

:error
pause

:end
popd
```

- `:end` — 正常结束，`popd` 恢复原工作目录
- `:error` — 出错时 `pause` 等待用户按键，让用户能看到错误信息

### Setup.bat 实际流程

```
Setup.bat
│
├─ [1] 运行 GitDependencies.exe（下载 10-20GB 二进制依赖）
│      → 生成 .gitdeps, BinaryPrerequisitesMarker.dat,
│        UEPrereqSetup_x64.exe, UnrealVersionSelector 等
│
├─ [2] 安装 git hooks（post-checkout + post-merge）
│
├─ [3] 运行 UEPrereqSetup_x64.exe（安装 VC++ Redist 等系统前提）
│
├─ [4] 注册引擎安装到注册表
│
└─ 完成
```

## 三、GenerateProjectFiles.bat（内层实现）

> 路径：`G:\UnrealEngineCarla\Engine\Build\BatchFiles\GenerateProjectFiles.bat`

```bat
@echo off

setlocal
echo Setting up Unreal Engine project files...
```

标准开头。

```bat
rem ## First, make sure the batch file exists in the folder we expect it to.
if not exist "%~dp0..\..\Source" goto Error_BatchFileInWrongLocation
```

- `%~dp0` = `Engine\Build\BatchFiles\`
- `%~dp0..\..\Source` = `Engine\Source`
- 检查 `Engine\Source` 是否存在，确保脚本在正确位置运行

```bat
rem ## Change the CWD to /Engine/Source
pushd "%~dp0..\..\Source"
if not exist ..\Build\BatchFiles\GenerateProjectFiles.bat goto Error_BatchFileInWrongLocation
```

- 切换到 `Engine\Source` 目录
- 再次验证脚本位置（通过相对路径反查）

```bat
rem ## Check that we have a Binaries directory with at least one dependency
if not exist ..\Build\BinaryPrerequisitesMarker.dat goto Error_MissingBinaryPrerequisites
```

- **关键检查** — 验证 `Engine\Build\BinaryPrerequisitesMarker.dat` 是否存在
- 这个文件是 `Setup.bat` 成功下载二进制依赖后生成的标记
- 如果不存在，说明 `Setup.bat` 还没运行过（或失败），报错退出
- **你当前的状态：此文件不存在，会触发此错误**

```bat
rem ## Verify that dotnet is present
call "%~dp0GetDotnetPath.bat"
if errorlevel 1 goto Error_NoDotnetSDK
```

- 调用 `GetDotnetPath.bat` 查找 .NET SDK
- UE5.5 的 UnrealBuildTool 用 `dotnet` 命令运行（不再是独立 exe）
- 找不到 .NET SDK 就报错退出

```bat
rem ## Build UnrealBuildTool if necessary
call "%~dp0BuildUBT.bat"
if errorlevel 1 goto Error_UBTCompileFailed
```

- 调用 `BuildUBT.bat` 编译 UnrealBuildTool（C# 项目）
- 如果 UBT 源码有变动会重新编译
- **这是你当前缺失的步骤 — UBT 尚未编译**

```bat
rem ## Run UnrealBuildTool to generate Visual Studio solution and project files
dotnet ..\Binaries\DotNET\UnrealBuildTool\UnrealBuildTool.dll -ProjectFiles %*
if errorlevel 1 goto Error_ProjectGenerationFailed
```

- **核心步骤** — 用 `dotnet` 运行 `UnrealBuildTool.dll`
- 参数 `-ProjectFiles` — 指示 UBT 生成 VS 项目文件
- `%*` — 透传用户的参数（如 `-2022` 指定 VS 版本）
- UBT 会：
  1. 扫描 `Engine/Source/` 下的所有 `.Build.cs` 模块描述文件
  2. 解析模块间依赖关系图
  3. 生成 `UE5.sln`（VS 解决方案文件）
  4. 为每个模块生成 `.vcxproj`（C++ 项目文件）

```bat
rem ## Success!
popd
exit /B 0
```

成功结束，恢复工作目录。

### 错误处理标签

| 标签                               | 触发条件                                                   |
| ---------------------------------- | ---------------------------------------------------------- |
| `Error_BatchFileInWrongLocation`   | 脚本不在正确目录                                           |
| `Error_MissingBinaryPrerequisites` | `BinaryPrerequisitesMarker.dat` 不存在（Setup.bat 未运行） |
| `Error_NoDotnetSDK`                | .NET SDK 未安装                                            |
| `Error_UBTCompileFailed`           | UnrealBuildTool 编译失败                                   |
| `Error_ProjectGenerationFailed`    | UBT 生成项目文件失败                                       |

### GenerateProjectFiles.bat 实际流程

```
GenerateProjectFiles.bat (外层)
│
└─ call Engine\Build\BatchFiles\GenerateProjectFiles.bat (内层)
    │
    ├─ [1] 检查 Engine\Source 存在
    ├─ [2] 检查 BinaryPrerequisitesMarker.dat ← 需要 Setup.bat 先运行
    ├─ [3] 查找 .NET SDK (GetDotnetPath.bat)
    ├─ [4] 编译 UnrealBuildTool (BuildUBT.bat) ← 首次必须
    ├─ [5] 运行 UBT -ProjectFiles 生成 UE5.sln + .vcxproj
    │
    └─ 完成
```

## 四、在 CarlaSetup.bat 中的完整上下文

```bat
:: 克隆 UE5 源码（已完成）
git clone -b ue5-dev-carla https://github.com/CarlaUnreal/UnrealEngine.git UnrealEngine5_carla

:: 设置环境变量
pushd UnrealEngine5_carla
set CARLA_UNREAL_ENGINE_PATH=!cd!
setx CARLA_UNREAL_ENGINE_PATH !cd!

:: 1. 下载二进制依赖（10-20GB）
call Setup.bat
::   → GitDependencies.exe 下载依赖
::   → 安装 git hooks
::   → UEPrereqSetup_x64.exe 安装系统前提
::   → UnrealVersionSelector 注册引擎

:: 2. 生成 VS 项目文件
call GenerateProjectFiles.bat
::   → 检查前提标记文件
::   → 编译 UnrealBuildTool (C#)
::   → UBT 生成 UE5.sln + .vcxproj

:: 3. 编译引擎（1小时+）
msbuild Engine\Intermediate\ProjectFiles\UE5.vcxproj ^
    /property:Configuration="Development_Editor" ^
    /property:Platform="x64"
```

三步关系：

```
Setup.bat                GenerateProjectFiles.bat          MSBuild
   ↓                            ↓                            ↓
下载二进制依赖    →    生成 VS 项目文件       →     编译引擎源码
(10-20GB)              (UE5.sln, .vcxproj)        (cl.exe 编译 C++)
```

## 五、你接下来要做的事

### 第 1 步：运行 Setup.bat（下载二进制依赖）

在 **x64 Native Tools Command Prompt for VS 2022** 中：

```cmd
cd /d G:\UnrealEngineCarla
Setup.bat --force
```

- `--force` — 跳过逐文件确认，无人值守运行

- 需要网络代理的话，先设置：

  ```cmd
  set HTTP_PROXY=http://127.0.0.1:11888
  set HTTPS_PROXY=http://127.0.0.1:11888
  ```

- 这步下载 10-20GB，耗时取决于网速

### 第 2 步：运行 GenerateProjectFiles.bat

```cmd
GenerateProjectFiles.bat -2022
```

- `-2022` — 指定使用 VS 2022 的项目格式

### 第 3 步：编译引擎

```cmd
msbuild Engine\Intermediate\ProjectFiles\UE5.vcxproj /property:Configuration="Development_Editor" /property:Platform="x64"
```

- 最耗时的一步，1 小时+

### 第 4 步：更新环境变量

之前的 `CARLA_UNREAL_ENGINE_PATH` 指向 `G:\UnrealEngine5_carla`，需要改为新路径：

```cmd
setx CARLA_UNREAL_ENGINE_PATH "G:\UnrealEngineCarla"
```

然后**重开终端**使环境变量生效。
