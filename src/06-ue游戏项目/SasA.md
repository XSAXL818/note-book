# 以下为询问AI开发独立游戏所需要的过程文档

作为学生用 UE 做独立游戏作品集，文档是面试官判断你"真的做过"和"能独立解决问题"的核心证据。下面按开发阶段详细拆解每个阶段需要什么文档、写什么内容、以及为什么面试需要它。

---

## 一、概念设计期

### 1. 核心玩法一页纸 (One-Pager)
- **写什么**：用一段话 + 一张草图说清"玩家在什么世界、做什么操作、追求什么目标"
- **为什么重要**：面试时 30 秒内让面试官理解你的游戏，体现你的设计表达能力
- **格式**：1 页 PDF 或 Markdown

### 2. GDD (Game Design Document) 游戏设计文档
- **写什么**：
  - 游戏类型与核心循环 (Core Loop)
  - 玩家操作与交互设计
  - 关卡流程与节奏设计
  - 数值系统（血量、伤害、经济等）
  - 美术风格定义 + Moodboard（参考图拼贴板）
- **注意**：独立游戏不需要上百页 GDD，5-10 页聚焦核心系统即可，但必须体现你**从模糊想法到可执行方案**的转化过程
- **面试价值**：展示你系统化思考游戏设计的能力，不是"想到哪做到哪"

### 3. 原型验证记录
- **写什么**：
  - 用 UE Blueprint 或 C++ 做的核心玩法原型截图/录屏
  - 验证结论："好玩/不好玩，为什么，如何调整"
- **面试价值**：证明你遵循了"先验证再生产"的专业流程，而非盲目开发

---

## 二、预生产期

### 4. TDD (Technical Design Document) 技术方案文档
- **写什么**：
  - **UE 项目架构**：GameMode / GameState / PlayerController 等类的职责划分
  - **核心技术选型**：为什么用 Niagara 而非 Cascade？为什么用 C++ 而非纯 Blueprint？为什么用 Behavior Tree 而非状态机？
  - **关键系统设计**：如 AI 系统、存档系统、UI 框架的类图/流程图
  - **第三方插件/资产**列表及使用理由
- **面试价值**：这是**最核心的技术文档**，面试官通过它判断你的架构思维和技术深度

### 5. 资源管线与命名规范
- **写什么**：
  - 文件夹结构：`Content/Characters/` / `Content/Environment/` / `Content/Blueprints/` 等
  - 命名规则：`BP_` 前缀蓝图、`M_` 材质、`T_` 贴图、`SM_` 静态网格体、`SK_` 骨骼网格体
  - UE 的 Data Asset 和 DataTable 使用规范
- **面试价值**：体现工程规范意识，大型项目必备素养

### 6. 里程碑计划 (Milestones)
- **写什么**：
  - M1：核心玩法可玩（Vertical Slice）
  - M2：完成第一个完整关卡
  - M3：全部内容 + 音效
  - M4：优化打磨 + 发布
- **面试价值**：展示项目管理能力和时间把控意识

---

## 三、正式生产期

### 7. 开发日记 (DevLog) — 最重要
- **写什么**（每周 1 篇）：
  - 本周完成了什么（附截图/录屏）
  - 遇到了什么问题
  - 如何解决的（思路 → 尝试 → 结果）
  - 下周计划
- **格式建议**：
  ```markdown
  ## DevLog #12 — 2026.05.26
  
  ### 本周完成
  - 实现了敌人的巡逻 AI（Behavior Tree + EQS）
  - 角色受击反馈（Anim Notify + Camera Shake）
  
  ### 遇到的问题
  - EQS 在复杂地形下查询缓慢（~15ms/帧）
  - 解决方案：改用缓存 + 异步查询，降至 2ms
  
  ### 下周计划
  - Boss 战逻辑
  - 存档系统
  ```
- **面试价值**：这是你"持续开发能力"的硬证，面试官最爱看，还能发布到 B站/知乎/掘金积累影响力

### 8. 技术难点与解决方案 — 面试杀手锏
- **写什么**（每个难点独立一篇）：
  - 问题描述（现象 + 根因分析）
  - 尝试方案 A → 失败原因
  - 尝试方案 B → 失败原因
  - 最终方案 C → 成功 + 性能数据对比
- **UE 常见技术难点举例**：
  | 领域 | 典型难点 |
  |------|---------|
  | 渲染 | 自定义材质的 Shader 优化、Lumen 实时 GI 的场景适配 |
  | AI | 大量 NPC 的 LOD AI、Behavior Tree 的性能瓶颈 |
  | 网络 | UE 的 Replication 机制理解与调优 |
  | 物理 | Chaos 物理引擎的稳定性和性能取舍 |
  | 动画 | Animation Blueprint 的状态机设计、Anim Dynamics |
  | GC | UObject 的内存泄漏排查与优化 |
  | Blueprint | 蓝图与 C++ 的职责边界和性能平衡 |
- **面试价值**：面试官通过你的"踩坑-填坑"过程判断你的问题解决深度，比最终结果更有说服力

### 9. 版本变更日志 (Changelog)
- **写什么**：每个版本的功能清单 + Bug 修复清单
- **格式**：`CHANGELOG.md`，遵循 [Keep a Changelog](https://keepachangelog.com/) 格式
- **面试价值**：体现你对项目状态的掌控力

---

## 四、测试优化期

### 10. 性能优化记录
- **写什么**：
  - 优化前的 Profile 数据（UE Profiler / Stat 命令截图）
  - 优化措施
  - 优化后的对比数据
  - 典型指标：FPS、Draw Calls、GPU Time、内存占用
- **面试价值**：游戏行业极度重视性能优化能力，有数据支撑的优化记录比任何口头描述都有力

### 11. Bug 记录与归档
- **写什么**：关键 Bug 的复现步骤、根因分析、修复方案
- **面试价值**：展示你的调试方法论（不是靠运气修 Bug）

---

## 五、发布展示期 — 作品集包装

### 12. 作品集展示页 / README
- **写什么**：
  - 项目简介（1 段话 + 封面图/GIF）
  - 核心技术亮点（3-5 条，每条配代码片段或截图）
  - 我的职责（如果是团队项目，明确分工）
  - 技术栈清单
  - 演示视频链接
- **面试价值**：GitHub README 就是你的门面，HR 筛简历第一眼就看你这个

### 13. 技术博文 / 演讲 PPT
- **写什么**：从 DevLog 和技术难点中提炼 1-2 篇深度文章
- **发布平台**：知乎、掘金、Gitee、个人博客
- **面试价值**：公开输出是技术影响力的证明，大厂非常看重

---

## 面试视角的文档优先级

如果时间有限，按这个优先级来：

| 优先级 | 文档 | 理由 |
|--------|------|------|
| P0 | 开发日记 (DevLog) | 持续性 > 完美性，证明你做完了整个项目 |
| P0 | 技术难点与解决方案 | 面试核心考点，"踩坑填坑"最有说服力 |
| P0 | TDD 技术方案文档 | 证明架构设计能力 |
| P1 | 性能优化记录 | 游戏行业硬指标 |
| P1 | 作品集展示页/README | 面试入口 |
| P2 | GDD | 设计思维证明 |
| P2 | 里程碑计划 | 项目管理证明 |
